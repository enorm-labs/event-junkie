# Scanner denominators — a floor that only moves up. See #1087 and scripts/scan-coverage.sh.
#
# Each number says how much a gate looked at, not what it found. A drop fails the gate, because a
# scanner covering less ground reports success exactly as loudly as one covering all of it.
#
# Raise a number in the commit that adds the coverage; lower one only with a reason in the pull
# request, and never to make a red check green. `scripts/scan-coverage.sh update <key> <file>` writes
# the row from a real run rather than from a guess.
#
# Trivy and Dependency-Check are deliberately absent. Their counts move with an upstream advisory
# database, so a number here would rot; both assert a floor of zero instead.
#
# The ZAP rule counts are exact for the pinned image. The ZAP URL counts are a spider's, and a
# spider does not find the same number every run: the k3d full scan found 217 URLs on a laptop and
# 107 on the runner, the production baseline 27 and 214. So those three floors sit at about half of
# the smallest count seen, which is the line between a scan that saw the site and one that saw a
# 429 wall or a Traefik that never came up. `update` them from a real run only for a reduction that
# is meant. An active rule set to IGNORE in `.zap/rules-*.tsv` is not run at all (the full scan
# prints it as SKIP) and leaves the rule count, so an IGNORE on an active rule lowers that floor by
# one in the same commit.
