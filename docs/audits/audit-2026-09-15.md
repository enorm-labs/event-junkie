### 2.2 Duplication & missing abstractions — ⚠️ 2 findings

#### 🔴 high — 29 single-page importers repeat the same `importEvents` body

**Where:** 35 files under `events-importer/src/main/kotlin/de/norm/events/scraper/*/`, 29 of them identical in shape.

**Evidence:**

```
$ grep -rl 'when (val fetchResult = htmlFetcher.fetch(url, etag, lastModified))' \
    events-importer/src/main/kotlin/de/norm/events/scraper/ | grep -vc AbstractTwoPage
35
$ grep -rl 'val events = overviewPageScraper.scrape(fetchResult.document, url)' \
    events-importer/src/main/kotlin/de/norm/events/scraper/ | wc -l
29
```

`ClashWebsiteImporter.kt:36-56` is the representative copy:

```kotlin
override suspend fun importEvents(url: String, etag: String?, lastModified: String?): ImportResult =
    when (val fetchResult = htmlFetcher.fetch(url, etag, lastModified)) {
        is FetchResult.NotModified -> { ImportResult.NotModified }
        is FetchResult.Success -> {
            val events = overviewPageScraper.scrape(fetchResult.document, url)
            logger.info { "Scraped ${events.size} event(s) from Clash" }
            ImportResult.Success(events, fetchResult.etag, fetchResult.lastModified)
        }
    }
```

**Why it matters:** `AGENTS.md` records that single-page HTML venues "implement `EventImporter` directly instead". That is true. It does not say that each one
must re-type the conditional-request handling.

Any change to that handling costs 29 edits. A new `FetchResult` case, a log field, or a dropped-event counter like the one `AbstractTwoPageWebsiteImporter`
already carries. An importer that misses the change fails in a way only a re-seed shows. A new venue is also copied from one of these files, so the count grows
by one per venue.

**Recommendation:** add `AbstractSinglePageWebsiteImporter(htmlFetcher, scraper)` beside the two-page base. It owns the fetch orchestration and the
`NotModified` branch, and takes the log line's venue name from `eventSource`. Each of the 29 importers then declares a constructor and its `VenueLimitations`,
and nothing else.

The six remaining files keep their own `importEvents`. Those are the shared-detail-page and derived-occurrence shapes that ADR-007 records, and they are not
this finding.

#### 🔴 high — 24 two-page importers forward to their scrapers byte-identically

**Where:** 24 of the 28 `AbstractTwoPageWebsiteImporter` subclasses.

**Evidence:**

```
$ grep -rl '): List<ScrapedEvent> = overviewPageScraper.scrape(document, url)' \
    events-importer/src/main/kotlin/de/norm/events/scraper/ | wc -l
24
$ grep -rl '): ScrapedEvent? = detailPageScraper.scrape(document, url)' \
    events-importer/src/main/kotlin/de/norm/events/scraper/ | wc -l
24
$ grep -rl 'AbstractTwoPageWebsiteImporter(' \
    events-importer/src/main/kotlin/de/norm/events/scraper/ | wc -l
28
```

Every one of the 24 is the same eight lines, e.g. `AlteKantineWebsiteImporter.kt:41-49`:

```kotlin
override fun scrapeOverview(document: Document, url: String): List<ScrapedEvent> =
    overviewPageScraper.scrape(document, url)

override fun scrapeDetail(document: Document, url: String): ScrapedEvent? =
    detailPageScraper.scrape(document, url)
```

**Why it matters:** this is a hop that forwards and is named no better than what it forwards to. The abstract methods exist to let a subclass do something
other than delegate, and 24 of 28 do not. The four that differ are the interesting ones and are currently indistinguishable from the 24 that do not.

**Recommendation:** give the base class two constructor parameters. An overview scraper and a detail scraper, each a small functional interface over
`(Document, String)`. Keep the two methods `open`, and default them to those parameters. The 24 subclasses then lose eight lines each, and the four real
overrides become visible as overrides.

`fillGapsFromOverview` stays abstract. It is the venue's merge strategy and it differs per venue. Only Modus and Ritter Butzke share an implementation.

#### 🟢 low — near-identical `htmlToText` and `splitActs` helpers are **not** duplication

Four `htmlToText` and six `splitActs` private helpers exist across venue packages
(`grep -rn "fun htmlToText\|fun splitActs" events-importer/src/main/kotlin/de/norm/events/scraper/*/`). Reading all ten shows each differs in a
behaviour-carrying way — `wholeText()` versus `text()`, `&nbsp;` normalisation, blank-line runs, whether a parenthesised act is split. Extracting a shared
helper would change what lands in the database at some venues. **Recorded here so the next audit does not re-raise it as a finding.**

### 2.3 Tests & safety net — ⚠️ 1 finding

#### 🟡 medium — eight scraper helpers were `internal` with no test reaching them

**Evidence:** an index of every whole-word token in every tracked `.kt` file, intersected against top-level non-private declarations, found 8 declared wider
than their only reference:

```
.../scraper/binuu/BinuuOverviewPageScraper.kt:103         internal fun binuuDetailUrl
.../scraper/columbiahalle/ColumbiahalleOverviewPageScraper.kt:223  internal fun parseGermanYearMonth
.../scraper/columbiatheater/ColumbiaTheaterDetailPageScraper.kt:115 internal fun firstTicketUrl
.../scraper/loge/LogeDetailPageScraper.kt:145             internal fun mapSchemaEventStatus
.../scraper/madameclaude/MadameClaudeApiScraper.kt:370    internal fun isDjSetTitle
.../scraper/saalchen/SaalchenOverviewPageScraper.kt:196   internal fun parseNoticeTime
.../scraper/saalchen/SaalchenOverviewPageScraper.kt:211   internal fun parseSinglePrice
.../scraper/silentgreen/SilentGreenEventFields.kt:105     (public) fun stripHostPrefix
```

`git grep -nw <name> -- '*.kt'` returns exactly two lines for each: the declaration and its single call site in the same file.

**Why it matters:** `internal` on a file-local helper usually means a test reaches in. No test does. The venue's saved fixture covers each one indirectly,
which is real coverage. But it leaves each helper's own edge cases asserted only where a fixture happens to hold one. `firstTicketUrl` handles a concatenated
shop link, and `parseSinglePrice` handles a bare amount as well as a `€`-prefixed one. This is the shape of #726.

**Recommendation applied:** all eight are now `private`, so the visibility states the truth.

**Not applied:** direct tests for `firstTicketUrl` and `parseSinglePrice`. Their KDoc describes an edge case no fixture is guaranteed to hold. A new test is not
a refactor and belongs in its own change.
